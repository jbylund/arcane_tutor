STAGE 4 -- an estimate of 0 claims EMPTINESS, and only the proven channel may claim it.

THE BUG. `c:bu t:whale` reported matches=0 in all three unique= modes while card_guaranteed was 17
and the true totals were 1/2/1. Not a cross-space inference, as first framed: est_cards_before_and_arm
is calibrated_balls_into_bins(printing_matches, n_cards), so card is DERIVED from printing, and the
And arm's card bound is applied only as a .min() clamp -- which can lower but never raise. A printing
estimate of 0 therefore collapses card and artwork too, and a correct card bound of 17 is powerless.

THE SOURCE. An independence product rounding below 0.5 emits 0. Over 32,745 And roots:
    estimate 0 AND guaranteed 0     2,418   proven empty -- must stay 0
    estimate 0 BUT guaranteed > 0   1,347   guessed empty
      of those, truly empty         1,266   right by luck
      of those, NOT empty              81   predicted_matches 0 for up to 30 real results

THE FIX, two parts.
  1. raise_unproven_zero_estimate: raise a 0 guess to 1 when a nonzero bound exists. Mirror of
     stage 1's clamp; together `1 <= estimate <= guaranteed`. A PROVEN zero is untouched, which is
     what keeps matches == 0 meaning "proved empty".
  2. Candidate::BoundedEstimate. Part 1 alone broke two tests, correctly: the rest_max mechanisms
     folded `indep.min(rest_max)` as a single ESTIMATE, so a rest_max of 0 was a PROVEN emptiness
     stored as a mere guess, which part 1 would have destroyed. Both sites' own comments had already
     named recording the bound separately as a deferred follow-up. Now rest_max goes to guaranteed,
     indep to estimate, and routing_cardinality() takes the min. Inert on every accuracy read by
     construction: min(g_old, min(indep, rest)) == min(min(g_old, rest), indep).
